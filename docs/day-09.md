# Day 9 · 设计一份可以对照原文的简历画像

2026-11-03 开始。起点是 Day 8 提交 `ec4609c`，开工时全套测试为 `24 passed, 1 warning`。今天的目标是用一段虚构简历设计画像，再用 Python 校验一份手工填写的样例。

## 第一关 · 如果你是面试官

把这三句当作昨天预览接口返回的 `text`：

> 项目：简历预览工具。
> 我用 FastAPI 实现了文件上传，用 pytest 验证了空文件的处理。
> 接下来想学 Redis。

先选一项可以据此追问的技能，抄下支持它的一句原文。再判断 Redis 能不能放进“实际用过的技能”，说说理由。最后只保留第三句，想想此时技能列表和项目列表应该填什么。先在聊天里回答，再把定下来的规则写成代码。

## 两份列表分别给谁用

| 字段 | 收录条件 | 面试时的用途 |
| --- | --- | --- |
| `skills` | 原文明确说用过的技术或工具 | 选择技术追问，例如候选人怎样验证一个接口 |
| `projects` | 原文明确给出名称的项目 | 让候选人围绕这个项目讲自己做过什么 |

两份列表都必填。每一项有 `name`（名称）和 `evidence`（逐字摘自原文的依据）。原文没有符合条件的条目，就传空列表 `[]`。这样可以区分“检查过了，没有可提取的条目”和“提取结果漏了一个字段”。这里的空列表只描述这份材料，用它不能断言候选人没有相关经历。

## 第二关 · 从一条记录写到整份画像

在 `app/resume_profile.py` 定义两个 Pydantic 模型。先写 `ProfileItem`，沿用 Day 4 学过的规则，要求 `name` 和 `evidence` 去掉首尾空白后都至少有一个字符。再写 `ResumeProfile`，用 `list[ProfileItem]` 声明上面的两个必填字段，允许列表为空。两个模型都拒绝多余字段。用第一关的答案手工构造一份字典，调用 `ResumeProfile.model_validate(...)` 检查。

结构校验能发现空名称或缺字段。要发现引文是编出来的，还得拿到原文。写一个单独的函数 `check_profile_evidence(profile: ResumeProfile, source_text: str) -> None`：逐条检查非空引文是不是原文的连续片段，找不到就抛出 `ValueError`，在提示里带上条目名称。即使引文找得到，“想学 Redis”能否支持“用过 Redis”仍需要按第一关的规则判断。

Day 8 的路由负责从文件得到正文。今天先让手工样例走通“候选画像 → 字段校验 → 引文与正文核对”。之后接 DeepSeek 时，模型可以提供候选画像；用户仍能看到每一项的原文依据，再决定哪些内容用于出题。

## 第三关 · 用反例验收

在 `tests/test_resume_profile.py` 中分别验证：

1. 合法画像能保留名称和引文，两份空列表也合法。
2. 删除整个 `skills` 字段，或把一项的引文改为纯空白，结构校验报 `ValidationError`。
3. 保留合法的字段类型，只把引文改成原文里没有的一句，结构校验能通过，引文核对函数要拒绝它。恢复原句后应能通过核对。

先运行 `uv run python -m pytest tests/test_resume_profile.py -q`，最后再运行 `uv run python -m pytest -q`。完成后选一个反例，用自己的话记录“哪一步发现问题，以及为什么”，然后整理当日提交。
