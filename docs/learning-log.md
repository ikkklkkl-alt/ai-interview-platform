### 我如何理解查询参数与校验

`?limit=2` 就是传入数量 2，不传时默认是 3。函数里要用 `directions[:limit]`，才会跟着参数变化。

`int` 负责按整数解析，`Query(ge=1, le=10)` 限制范围。参数不符合要求时返回 422，不会进入函数执行切片。

### 我的预测、实际验证结果与修正

一开始把 get 写成了 gat，导致启动报错。后来又把切片写死成 `[:3]`，传什么都是三条，改成 `[:limit]` 后才正常。

没加范围校验时，0 返回空列表，-1 返回前两条，因为 `[:-1]` 不包含最后一个元素。加了校验后，0、-1、11 和 abc 都返回 422。1 返回一条，2 返回两条，10 也只有现有的三条。

8001 被占用了，就换成 8002。访问 `/` 返回 404，要访问自己定义的完整接口路径。

### 我如何理解结构化输出与校验

`response.json()` 先解析接口返回的外层数据；里面的 content 还是字符串，要再用 `json.loads()` 解析，才能得到题目字典。

`model_validate()` 按字段规则校验，返回 Pydantic 对象；可以用 `.question` 取属性，用 `model_dump()` 转回字典。JSON 能解析，不代表里面的字段符合要求；通过字段校验，也不代表题目内容一定正确。

choices 是列表，要用 `[0]` 取第一个结果；choice 是字典，用 `["message"]` 取对应的值。先检查类型和列表是否为空，再读取里面的数据。

后来把 choices 当成字典检查，还混用了 choices 和 choice，导致正常响应也失败。根据每一层的数据类型改正后通过。

提示词不能只说“与类定义一致”，模型看不到本机的类，需要把具体规则和 JSON 示例写进去。有几次编辑后忘了保存，检查时读到的还是旧代码。

### 我如何理解自动化测试

assert 检查实际结果是否符合预期。pytest.raises 用来确认预期异常确实发生，错误数据被正确拒绝也可以是测试通过。

`5 passed` 数的是通过的测试用例，不是 assert 数量。检查 errors[0] 只检查第一条错误，`assert len(errors) == 1` 还能确认只有一个错误。数量、字段位置和错误类型要分别写断言；`assert 条件, 表达式` 的逗号后面是失败提示，不是第二个检查条件。

monkeypatch 临时替换 httpx.post，让 main 拿到准备好的响应；capsys 读取程序打印的内容。fake_post 收到的 kwargs["json"] 是发出的请求体，response_body 是返回的响应体。

这次保留了 main 里的解析、校验和输出，只替换访问外部模型的位置。测试通过说明程序能处理这些预设情况，还不能说明真实服务可用或题目质量足够好。现在先理清这些职责，后续有复用需求时再考虑拆分。
